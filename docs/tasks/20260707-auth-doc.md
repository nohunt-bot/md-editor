## 已從實碼抽出的權限事實（派工單依此，agent 需再對照核實）
身分模型：CurrentUser{userId, displayName, teamRoles:Map<teamId,Role>, admin}
- Role enum：EDITOR / VIEWER（僅兩種團隊角色）
- admin 是布林旗標，非團隊角色；admin canEdit/isMember 任意團隊皆短路 true，
  但 admin.teamRoles 為空 → 「複製到團隊」因無目標團隊可選而被擋
- isMemberOf(teamId)=teamRoles 含該 key；canEdit(teamId)=admin 或該團隊角色==EDITOR

身分來源（dev-stub，Keycloak deferred）：DevCurrentUserProvider 讀 X-Dev-User
header → 查 application.yml app.dev-users → 缺 header/未知使用者 → Unauthorized。
CurrentUserProvider 介面是未來接 Keycloak 的縫。

四個授權檢查（AuthorizationService）＋失敗語意：
- requireTeamMember(teamId)：成員或 admin 過；非成員→**403**（清單類端點，
  團隊是明確參數，不需隱藏存在性）
- requireCanEdit(teamId)：canEdit 過；成員但 viewer→**403**；非成員→**403**
- requireResourceReadable(teamId, openAndPublished)：admin/成員/open+published 過；
  否則→**404**（不可洩漏私有資源存在性）
- requireResourceEditable(teamId)：canEdit 過；admin/成員但 viewer→**403**；
  非成員→**404**

例外→HTTP（GlobalExceptionHandler）：Unauthorized→401、Forbidden→403、
ResourceNotFound→404、Conflict/OptimisticLockingConflict/IllegalState→409。
